# Python Workflow Skills Pack

This folder contains a reusable Python workflow for professional delivery from idea to release.

## Included Skills

1. `python-requirements-author`
2. `python-architecture-designer`
3. `python-roadmap-planner`
4. `python-module-implementer`
5. `python-integration-finisher`
6. `python-test-strategy`
7. `python-quality-gates`
8. `python-release-ops`
9. `python-project-template-scaffolder`

## Optional Upstream Skill

- `fsd-writer` (recommended): produce a detailed Functional Specification Document before requirements drafting.

## What This Is For

Use this pack when you want a repeatable development process:

- idea/FSD -> clear requirements
- requirements -> architecture and module contracts
- architecture -> sequenced roadmap
- roadmap -> module implementation and app integration
- integration -> testing, quality gates, and release readiness

## Install On A New Machine

1. Copy each skill folder in this directory into:
   `%USERPROFILE%\.codex\skills\`
2. Restart Codex (or start a new session).
3. Trigger skills by name in prompts (examples below).

## Recommended Phase Flow

1. `Preferred: Use $fsd-writer to produce a comprehensive functional specification (FSD).`
2. `Use $python-requirements-author to convert the idea/FSD into implementation-ready requirements: ...`
3. `Use $python-architecture-designer to design the architecture from these requirements (and FSD if available): ...`
4. `Use $python-roadmap-planner to produce a functional module roadmap from this architecture: ...`
5. `Use $python-module-implementer to implement module X from this roadmap: ...`
6. `Use $python-integration-finisher to wire modules and validate core flows: ...`
7. `Use $python-test-strategy to produce the layered test plan: ...`
8. `Use $python-quality-gates to define enforceable lint/type/test gates: ...`
9. `Use $python-release-ops to prepare deployment, rollback, and post-release checks: ...`

Alternative path:

1. `Use $python-requirements-author first when no FSD exists and you need a fast start.`
2. `Then use $fsd-writer in evolve mode to formalize/expand the spec from approved requirements.`

## Notes

- This pack is intentionally split into focused phase skills.
- Run modules iteratively; do not implement the entire app in one pass.
- Keep artifacts from each phase (requirements/design/roadmap) and feed them to the next phase.
- If an FSD exists, keep section-level traceability from FSD -> requirements -> architecture -> roadmap.
- Preferred FSD handoff file is `Documents/<project-name>-fsd.md` generated by `fsd-writer`.
